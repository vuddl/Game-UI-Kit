# Photoshop source and export

Use these rules for screen PSDs, reusable component masters and standalone UI element PSDs. Start from the approved design for each element. Choose geometry, colors and effects from that design and its intended use.

Apply [sprite fidelity, clean edges and effect calibration](sprite-quality.md) to native and embedded artwork alike. Preserve volume and reflection geometry, and match shadow/FX darkness or brightness, contact density, softness and extent to the demo. Layer-style defaults do not establish fidelity. Editable separation belongs inside the requested PSD; ordinary sprite PNGs contain the composed body and effects unless separate files were requested.

## Select Photoshop before creating files

On each PSD export, let the user choose the Photoshop installation first. The export form discovers installed versions on Windows from registry entries, running processes, common installation folders and Start Menu/Desktop shortcuts. It lists each version with its executable path, requires an explicit choice even for a single install, and accepts a manually entered `Photoshop.exe` path for an install it missed. PNG-only export needs no Photoshop choice.

The submitted `briefs/export.json` contains `photoshop: {path, label, version}`. `uikit.py psd` validates this executable before creating export assets and launches it directly. A runtime check of Photoshop's application path stops execution in a different installation. A missing or invalid choice requires reopening the export form; a launch failure requires reporting the error, with no automatic switch to another version. `--no-run` only prepares JSX for later execution.

Use the same selected installation for the component master, follow-up scripts, reopening and rendering. For standalone PSD requests outside the screen export form, run `py -3 <skill>/scripts/photoshop.py`, show the found versions and paths as a choice, then save the user's selection under `photoshop` in the export brief. If nothing is found, explain that a valid Photoshop path or an installation is needed before creating the PSD.

## Configure script execution in the export form

When the user selects a Photoshop installation (or finishes entering its path) in the export form, `/photoshop-config` verifies that executable and prepares `WarnRunningScripts 0` in its own user Settings folder's `PSUserConfig.txt`. Preserve unrelated settings and encoding, keep an original `.game-ui-kit.bak` when editing an existing file, and avoid rewriting an already-correct file. This setting disables external-script warnings for that selected Photoshop version, not just this skill's scripts.

The form shows the check result and a **Kiểm tra lại** button. Submission waits for a successful check. If Photoshop is not running, the preference is in place before its first scripted launch. If it was already running before the configuration was written, show `PHOTOSHOP_RESTART_REQUIRED`: the user saves their work, closes and reopens that Photoshop once, then clicks **Kiểm tra lại**. Do not close Photoshop, discard documents, click through its script-warning dialog or repeatedly launch JSX. The runner checks the preference and process start time again before every `-r` call; on restart/configuration errors it returns before sending a script. A version with an unresolvable Settings location requires correcting its metadata/path rather than editing another version's preferences.

## Choose the layer type

For a background taken from a demo, first follow [background separation and multisize](backgrounds.md). Keep the complete cleaned and expanded master at its actual pixel dimensions inside the background Smart Object. The screen PSD shows its uniform cover crop; do not discard the off-canvas image data or stretch the source independently along X and Y. Keep foreground subjects and UI separate, and deliver the full clean background PNG and its multisize QA/Unity guidance alongside screen PSDs. A redraw choice must preserve the same composition and crop behavior.

| Content | PSD construction |
|---|---|
| Reusable structural UI such as buttons, popups, panels, frames, title frames and bars | Native, editable Shape Layers and Photoshop Layer Effects. Keep content, icon and label separate from the reusable surface. |
| Any icon or decor | Preserve the approved artwork as an embedded Smart Object. Use native shapes for a flat, single-color silhouette or genuinely simple geometry that a gradient, shadow or stroke can reproduce. Use the same rule for nav icons, decorative leaves, badges and other UI art. Keep detailed originals instead of tracing them into color bands or many shapes. |
| Standalone illustration, prop or VFX | Isolate the whole intended asset as a clean, full-resolution RGBA PNG. Embed it as a Smart Object before scaling it in the layout. This applies to any standalone VFX in the design. |
| Avatar or other image in a shaped window | Place the complete square or rectangular image as an embedded Smart Object above a separate editable shape. Clip the image to the shape so the window, image scale and image position can be edited independently. Use the same setup for irregular windows. |
| Ordinary interface copy | Live text layers with the actual matched font and effects where supported. |
| Decorated title, sign, logo or emblem lettering | Prioritize faithful English artwork, exported as a transparent PNG with FX composed. Embed it as a full-resolution Smart Object; preserve an editable source when available/requested rather than forcing it into plain live text. |

Keep the original pixel dimensions inside each image Smart Object. Use the original file or isolate the asset at source resolution before placing it. A small screen crop or upscaled sprite cannot serve as the high-resolution source. For illustration clusters and VFX, check alpha on both light and dark backdrops. Preserve clean edges and intentional translucency, with no patches of the old backdrop or color fringing. Keep clean isolation separate from the clipping shape used to frame an image. Follow the export form's separate choice for the full-screen background.

Apply [reference-based typography](fonts.md): choose fonts per role, distinguish shadow from stroke and align glyphs to the main face excluding FX margins/decorative peaks. The native text requirement for ordinary copy does not override the preferred artwork treatment for stylized lettering. Check fonts and text effects in actual Photoshop renders, not just the presence of live layers.

## Build native shapes with a compact layer stack

1. Inspect the reference at its native size and final placement size. Identify the silhouette, surfaces, borders, light direction, edge roll-off, contact shadows and gloss. Use live rounded rectangles and ellipses where they fit. For irregular silhouettes use smooth Bézier curves with few anchors. Unite connected parts or subtract cutouts with path operations when a single editable silhouette makes the construction clearer.
2. Use **Bevel & Emboss on the main shape** for smooth thickness and roundness. Tune its size, depth, softness, contour and light from the reference. Add another shape for an independently adjustable material or a distinct lip when the design actually has one.
3. Use **Stroke on the main shape** for a flat outline, alongside the main bevel if the face needs one. If the outline itself has relief, duplicate the outline onto a stroke-only shape, apply Stroke to it, put it in a separate group and apply Bevel & Emboss to that group. Keep the face independent. Use Stroke on the enclosing group for a continuous border around several connected shapes, and nest groups when multiple continuous rims or glows need independent effects.
4. Use native gradients and layer styles for material and lighting. Clip directional gloss or shadows to their receiving surface when needed. Reserve separate shapes for features that need independent edits. Compound paths can keep stylized lettering compact, with separate face and lip only when both are visible. A Smart Object used for complex editable artwork can contain native shapes in its embedded document. Standalone VFX follow the image rule above, while effects that belong to a shape can stay native.
5. Group by visual hierarchy. A popup contains its panels and controls, and a control contains its surface, icon and text. Name element groups using the [UI kit standard](ui_kit_standard.md). Keep imported kit element names stable across screens. Name internal layers by their purpose, such as `face`, `rim`, `stroke` or `highlight_top`.

## Prepare the reusable component master

- Create `export/psd/components.psd` as a separate Photoshop master when delivering reusable components. Keep one named artboard per reusable sprite design at its optimized export size, separate from the screen-specific placements. Keep each artboard transparent and place its editable shape stack at actual pixel size. Reuse the same design across screens.
- Trim sprite canvases tightly around all visible art, retaining the full stroke, shadows and other intended effects. Add only enough transparent padding for both width and height to be multiples of four. Keep the fixed dimensions and matched loading fill and track canvases in the [UI kit standard](ui_kit_standard.md). Keep full-resolution Smart Object contents even when the outer export canvas is small.
- When delivering sprite PNGs from the master, export each artboard at actual size with transparency. Keep sprite names, dimensions and the kit's 9-slice data synchronized with the final exports.
- For Unity 9-slice, retain the non-stretching corners and rim, and leave a stretchable center or axis. Set left, right, top and bottom borders in sprite pixels for the final canvas. Use guides where useful and record the borders in the kit's 9-slice data. Recompute or verify them against the final PNG whenever the sprite canvas or visual borders change. Use `uikit.py nineslice` and the kit QA previews to check representative small and stretched sizes. Look for distorted corners, stretched details, seams and clipped effects. Resolve or report components that need manual slice work.
- Keep one canonical upright icon when horizontal flip, vertical flip or rotation reproduces the same artwork. Keep variants with distinct artwork. Use the normal button sprite for press feedback without exporting a new Press sprite.

## Build and verify the deliverables

1. Use [shape recipes](recipes.md) for supported editable constructions. `uikit.py recipe --auto` and its preview boards are draft aids. For screen exports, mark artwork to be preserved as `"role": "art"` and run `psd` with `--art image`. Use `"role": "ui"` where the name would otherwise route native UI to art. Respect any specific user direction to redraw an artwork. Inspect the output for automated traces or flattened structural UI and replace them with the intended layers before delivery.
2. `uikit.py psd` assembles screen PSDs in the selected installation. Build the component master there too. Finish constructions outside the recipe format in that Photoshop or with a targeted Photoshop script, including smooth compound curves and Smart Object clipping to a live shape. Open and save only the export documents. If the selected Photoshop cannot execute the generated `.jsx`, report the failure and that the PSD and its render are pending verification; ask the user to choose again before using another version.
3. Render the saved PSD in Photoshop and compare each rebuilt component against its approved demo. Align at the same visible size and compare on the same backdrop, checking silhouette, hue, depth, stroke, highlights and shadows at normal size and zoomed in. Require **at least 95% visual fidelity**. Record a repeatable image comparison, such as SSIM over the aligned artwork and edge region. Exclude unrelated background and excess empty padding. Review the material, edges and lighting visually as well. If the reference prevents a reliable score, record what could be verified and why a score was unavailable. Iterate on weak matches. Smoother edges and more polished effects are welcome when they retain the approved form and look.
4. Reopen the saved PSD and verify Shape Layers, live effects, group hierarchy, live text, full-resolution embedded sources and clipping relationships. Review screen check images at `export/psd/assets/<layout>_check.png` and render again after any Photoshop edits. Check fonts, missing effects and unintended upscaling. Report any unverified fidelity, unresolved mismatch or workaround with the affected element and deliver the file paths.
